## Change

The native producer owns format enumeration and the closed raster policy.
PNG and history/cloud policy bytes are retained alongside DIB/DIBV5. Bitmap is
regenerated by Windows from DIB. The two OLE bookkeeping formats are omitted
only after complete public OLE metadata proves this closed raster bundle.
Hidden/unknown formats, storage/file media, indexed content, target devices,
incomplete enumeration and unrelated OLE text bundles remain unsupported.

The metadata helper releases the clipboard before OLE calls, has a 2-second
deadline and 256-MiB process-family memory cap, emits at most 2048 bytes, and
retains ownership on failed cleanup. No image bytes or COM pointers cross its
protocol. Its proof is bound to the exact sequence and native format order;
the caller rechecks both under the clipboard lock before materializing bytes.
The existing 32-MiB snapshot limit, transaction ownership, target checks and
restoration rules remain in force. Ordinary non-OLE cases avoid the helper.

Temporary dictation text is explicitly excluded from clipboard history/cloud
processing. Original screenshot policy bytes are restored unchanged. No Windows
settings are changed. The approved UI, animation, original sounds, voices and
worker dependencies are unchanged.

Its [desktop text service](https://github.com/EpicenterHQ/epicenter/blob/a6b15c28db9076742d7ae7014f8ec9f97aa615d1/apps/whispering/src/lib/services/isomorphic/text/desktop.ts)

That command tries to save text, treats a failed text read as absent, writes the
transcript, waits50ms, sends Ctrl+V on Windows, waits100ms and restores only a
successfully saved text value. There is no image or all-format snapshot in that
command. Thus an image-only clipboard does not trigger Hugin's format rejection,
but the image is replaced rather than preserved. This is an implementation
comparison, not a new live Whispering test or a claim about all releases.
No upstream implementation code was copied into Hugin.
