# Faster first speech — 21 October 2026

The first section now has a soft 120-character budget. Later sections grow
toward 240 characters, preferring the first suitably sized sentence boundary.
Earlier whitespace and intact words take precedence over the soft budget;
single tokens retain the existing 240-character hard limit. A final remainder
up to 40 characters stays with its preceding phrase within that hard limit.

Actual audio generation and alignment still finish before each section plays.
The native sample clock still owns word highlighting. One successor prepares
during playback; no extra GPU concurrency, model, cache or timing estimates.
Style A, input bindings, clipboard, startup and preferences are unchanged.

## Real comparison

`tools/probe_reading_start.py --root C:/Users/brian/Hugin --run` used the current
Controller, real CUDA workers and native waveOut, replacing generated speech
with equal-length zero PCM only at the output. It used only the two synthetic
fixtures in that tool. The old section policy is frozen from main `9ec85225`.
The final production policy measured is `6b57416`; subsequent `1cdad90` changes
only failed probe-cleanup retries and their guard, not the measured reading path.

Warm measurements used the same resident workers, counterbalancing policy order
between fixtures. One completed pair per fixture/voice; no percentile or universal
latency claim. First play means the first native buffer submission, not an acoustic
microphone measurement. All aligned first-word start samples were zero here.

Both policies align and mark every expected word: 54 in the paragraph and 43 in
the long sentence for each voice. No candidate section fell back to section-only
marking. Paragraph sections are 116/116/116 characters; long sentence 116/183.
The scheduling gap measures predecessor drain to successor submission, excluding
silence already generated by TTS. Existing/generated sentence pauses and prosody
need a listening check; silent output cannot establish perceived continuity.

The initial candidate was rejected despite faster starts: Tyr could not reliably
align a shifted 105-character remainder, and another case left a final word alone.
The refined natural boundaries and tail absorption fix these fixture cases without
relaxing alignment validity. Invalid alignment on other inputs still retains the
existing honest fallback rather than fabricated word times.

Cold baseline start was 26.539 s including worker/model initialization. Cold
candidate start was not separately measured; this change does not remove initial
model loading or the existing STT idle offload after 90 seconds. OS cache was not
controlled. Warm elapsed times include generated speech, whose duration changes
with phrasing, and are not pure computation measurements.

Shorter preparation trades a small observed CPU increase for earlier speech.
Peak committed memory was 8,453,021,696 bytes for the TTS process family and
3,247,095,808 for STT, cumulative across the shared-worker run. These are not
working set, GPU VRAM or a simultaneous total peak; those were not measured.
Entire measurement: 235.939 s elapsed, 6.516 s controller CPU. Both workers
reported CUDA, closed successfully and released the exclusive guard. No audio,
text, clipboard or personal input was persisted in its technical report.
